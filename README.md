## Что это

Бот поднимает полноценную сессию [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) — те же инструменты, тот же агентный цикл, те же скиллы и `CLAUDE.md`, что и в терминале. Отличие одно: там, где Claude Code рисует в терминале запрос разрешения, бот присылает карточку с кнопками.

```
🖥️  Claude wants to run rm -rf node_modules

    Пересобрать зависимости с нуля

    ┌────────────────────────────────┐
    │ rm -rf node_modules            │
    └────────────────────────────────┘

    [ ✅ Разрешить ]   [ 🚫 Отклонить ]
    [ ♾️ Всегда разрешать это        ]
    [ ✍️ Отклонить и объяснить ] [ ⏹️ Стоп ]
```

Агент стоит и ждёт нажатия столько, сколько нужно — документация SDK прямо разрешает держать колбэк разрешения открытым сколь угодно долго.

## Возможности

| | |
|---|---|
| **Живая сессия на чат** | Один `query()` со streaming input держит диалог открытым. Отсюда работают `interrupt()` и смена режима разрешений на лету. Контекст переживает перезапуск процесса через `resume`. |
| **Кнопки под ответом** | Продолжить · Дифф · Коммит · Тесты. Дифф и коммит появляются, только когда в проекте есть репозиторий и есть что коммитить. После нажатия снимаются: они про тот ответ, а не про следующий. |
| **Разрешения кнопками** | Разрешить · Отклонить · Отклонить и объяснить · Всегда разрешать · Стоп. «Всегда» пишет правило в `.claude/settings.local.json` и переживает сессию. |
| **Уточняющие вопросы** | `AskUserQuestion` становится опросом с кнопками — Claude уточняет требования, не выходя из задачи. |
| **Строка состояния** | Пока агент работает, сверху висит сообщение с последними шагами. Обновляется не чаще раза в полторы секунды, чтобы не упереться в лимиты Telegram. |
| **Проекты** | `/project имя` переключает рабочую папку. У каждого проекта своя история. |
| **Git из чата** | `/clone`, `/diff`, `/commit`, `/push`, `/pr` — обычный круг работы с кодом, не выходя в терминал. |
| **Голосовые** | Расшифровываются и показываются текстом, чтобы было видно, что бот расслышал. |
| **Скиллы и MCP** | Те же скиллы и `CLAUDE.md`, что в терминале, плюс MCP-серверы из `mcp.json`. |
| **Мини-игра** | 10 Claude-котов по расходу токенов и 12 достижений. |

## Коты

<img src="docs/claude-star.svg" alt="" width="28" align="left" hspace="10">

Чем больше токенов потрачено, тем солиднее кот. Кот смотрит в фас: квадратная голова, два уха углами, тёмные глаза, светлая морда с открытым ртом, усы по обе стороны, четыре лапы снизу, хвост справа. Заливка сплошная, без обводки — силуэт держится сам, за счёт крупной клетки.

В мини-аппе коты живые: цикл пять секунд, двенадцать кадров в секунду. Корпус качается, глаза моргают дважды за цикл, хвост машет вдвое чаще корпуса, головной убор съезжает набок и возвращается. Кадры щёлкают, а не перетекают: ключевые точки стоят на границах кадров, а `step-end` не даёт браузеру размазать пиксельную картинку. В сетке коты идут вразнобой — одинаковый такт у десяти штук читается как дребезг экрана. При `prefers-reduced-motion` всё замирает.

Рисунок разложен по слоям — хвост, корпус, глаза открытые и закрытые, убор, — и каждый слой выезжает отдельной группой SVG. Иначе анимацию не сделать: мигать должны только глаза, а кепка съезжать независимо от корпуса.

Все десять — один спрайт на сетке 22×20. Различают их цвет, головной убор, шея и хвост. Стажёр ходит налегке и с хвостом-поленом; дальше кепка, берет с шарфом, бандана, каска, цилиндр с бабочкой, визор, цилиндр с золотой лентой, корона с камнем — и у квантового колпак волшебника, плащ и искры вокруг. С третьего уровня хвост поднимается трубой, с седьмого загибается наружу.

Наряды намеренно не берут цвет шкуры: цилиндр остаётся чёрным, корона золотой, плащ фиолетовым, на каком бы коте они ни сидели.

## Вход

Два способа, бот различает их по форме секрета.

**По подписке.** `claude setup-token` выдаёт долгоживущий токен вида `sk-ant-oat01-…`;
он уходит агенту как `CLAUDE_CODE_OAUTH_TOKEN`, и работа идёт по лимитам подписки,
а не по деньгам. Остаток лимитов бот собирает из событий сессии и показывает
в `/status` и в мини-аппе.

**По приглашению.** У каждого свой Claude Code — это основной режим. Но любой,
у кого есть свой доступ, может позвать других на свою подписку через `/admin`:
позванному приходит сообщение, вводить ему ничего не нужно.

Подписки при этом не смешиваются. Ключ подбирается так: свой, если он есть,
иначе — того, кто позвал. Не «владельца бота», а именно пригласившего, поэтому
цепочка работает: позванный, подключив свой ключ, зовёт дальше уже на себя.

Статистика раздельная: расход пишется на того, кто работает, и кот в мини-аппе
у каждого свой. Владелец видит все свои токены, позванный — только то, что
потратил в боте сам.

Позванному можно поставить суточную квоту: `/admin quota НОМЕР 200000`, ноль
снимает. По умолчанию ограничения нет — позвали работать, а не считать каждый
шаг. Квота видна обоим: в списке `/admin` рядом с расходом за сегодня и в
мини-аппе — своя отдельной шкалой, чужие строкой под именем в коопе. Упёрся в
предел — задача не начинается, а человек видит, сколько взял и когда обнулится.

Отозвать доступ может тот, кто звал (и владелец машины). `/logout` убирает
только собственный ключ: позванному убирать нечего.

**По API-ключу.** Обычный `sk-ant-api03-…`. Тогда платится по счёту за токены.

Порядок распознавания важен: шаблон API-ключа шире и накрывает токен подписки
целиком, поэтому подписочный проверяется первым. Иначе токен уходил бы в
`ANTHROPIC_API_KEY`, Anthropic отвечал бы «API key is invalid», а бот молчал.

Модель выбирается отдельно — `/model`, от Haiku до Opus. Набор инструментов
одинаковый на всех: это обычный Claude Code, просто в чате.

## Установка

Нужен Node 22.5 или новее — ради встроенного `node:sqlite`, чтобы на сервере не собирать нативные модули.

```bash
npm install
```

```bash
cp .env.example .env
```

```bash
npm run keygen
```

Полученную строку — в `ENCRYPTION_KEY`. Ею шифруются API-ключи в базе; сменишь ключ — все сохранённые придётся вводить заново.

Дальше заполнить `.env`:

- `BOT_TOKEN` — от [@BotFather](https://t.me/BotFather)
- `ALLOWED_USER_IDS` — свой Telegram id. **Пустое значение = бот отвечает кому угодно**, то есть отдаёт шелл на машине любому, кто его найдёт. Первый в списке — владелец: только он распоряжается доступом и видит `/logs`. Остальных можно пускать из чата командой `/admin`, не трогая `.env` и не перезапуская бота; выданное так же и отзывается, а сам список из `.env` отсюда не отозвать — он последний рубеж, если базу потеряли.
- `GITHUB_TOKEN` — необязательный. Даёт агенту приватные репозитории и `gh`; им же работают `/clone`, `/push` и `/pr`.
- `WHISPER_URL` — необязательный. Адрес сервиса расшифровки с интерфейсом OpenAI. Пусто — бот честно скажет, что голос не разберёт.
- `PROXY_POOL` — необязательный. Адреса прокси через запятую, если до Anthropic нет прямой дороги.

Секрет доступа к Anthropic в `.env` не хранится: его вводит пользователь в чат,
и он ложится в базу зашифрованным.

```bash
npm run dev
```

Команд намеренно мало. Всё, что агент умеет сам, командой не дублируется: сжать

кружки, стикеры, гео, контакты и опросы. На незнакомый тип отвечает словами,
а не молчанием.

### Три места, где легко ошибиться

**Расход токенов накопительный.** `total_cost_usd` и `modelUsage` в streaming-сессии приходят как итог с начала сессии, а не за ход. Суммирование по всем `result` завысило бы расход в разы, поэтому `Conversation` хранит прошлый итог и пишет в статистику разницу.

**`canUseTool` нельзя оставить без ответа.** Возврат `null` — это fail-closed: вызов инструмента блокируется навсегда, без ошибки и без таймаута. Поэтому у каждого запроса есть таймаут, обработчик `abort` и аварийный отказ, если карточку не удалось отправить.

**`MainButton` существует и вне Telegram.** `telegram-web-app.js` создаёт объект в любом браузере, где кнопка — заглушка, которая ничего не рисует. Проверять её наличие бесполезно; настоящий клиент опознаётся по заполненным `initData` или по `platform !== "unknown"`.

## Голос и MCP

Голосовые уходят в сервис с интерфейсом OpenAI (`POST /v1/audio/transcriptions`),
адрес задаётся в `WHISPER_URL`. Зашитого бэкенда нет намеренно: голос —
чувствительные данные, и выбор получателя должен быть явным. Расшифровка
показывается в чате текстом, чтобы было видно, что бот расслышал. Запрос идёт
напрямую, мимо прокси: обход нужен только Anthropic.

Ответы бот умеет читать вслух: на голосовое отвечает голосом сам, а `/voice`
включает озвучку и для текста. Адрес синтеза задаётся `TTS_URL` — по умолчанию
он выводится из адреса расшифровки, у одного сервиса это соседние ручки. Перед
чтением текст чистится: куски кода превращаются в «фрагмент кода», ссылки в
«ссылка», разметка снимается — иначе на слух выходит каша, которую ещё и долго
слушать.

Долгие задачи можно не держать в основном диалоге: `/bg прогони тесты и почини`
запускает отдельную сессию в той же папке проекта. У неё свой контекст и свои
карточки разрешений, отчитывается она в тот же чат. Больше двух на чат не
пускается — карточки от трёх задач сразу уже не разобрать.

MCP-серверы описываются в `mcp.json` в формате Claude Code. Переменные вида
`${VAR}` подставляются из окружения, поэтому токены остаются в `.env`, а не в
репозитории. Сломанный конфиг не роняет бота — сервер просто не подключается.
Инструменты чтения одобряются автоматически: спрашивать разрешение на каждый
запрос к документации бессмысленно.

## Безопасность

- API-ключи шифруются AES-256-GCM; сообщение с ключом удаляется из чата сразу после приёма и в логи не попадает.
- `ALLOWED_USER_IDS` — единственное, что отделяет бота от произвольного выполнения кода на машине.
- Имена проектов санируются; рабочая папка не может выйти за пределы каталога пользователя.
- Mini App отдаёт данные только по валидной подписи `initData` со сроком годности сутки.
- Агент работает внутри `WORKSPACE_ROOT`, а не в корне файловой системы.
- Необратимое спрашивается **всегда**, даже в режиме «без вопросов». В нём SDK
  одобряет вызовы до `canUseTool`, то есть карточек нет вовсе — и об этом он
  честно пишет в лог. Поэтому короткий список необратимого (`src/agent/guard.ts`)
  проверяется хуком `PreToolUse`, который срабатывает раньше: удаление за
  пределами проекта, `sudo`, остановка контейнеров и служб, форс-пуш, разметка
  диска, `curl | sh`, правка `.env` и настроек самого сервиса. Список намеренно
  узкий: бот, переспрашивающий на каждой второй команде, приучает жать
  «разрешить» не глядя.
- Выкатка проверяет автора каждого нового коммита по списку из
  `/etc/claude-telegram/deploy-authors` — вне репозитория, чтобы его нельзя было
  дописать тем же пушем. Файла нет — выкатки нет.

## Доступность

Мини-апп проверен по WCAG 2.2 AA: контраст текста не ниже 4.91:1 в светлой теме и 6.21:1 в тёмной при норме 4.5, статусы переданы словом, а не только цветом, прогресс-бар объявляется фразой целиком, все иллюстрации помечены декоративными, тач-таргеты не меньше 44 px.

Цвета карточек намеренно **не** выводятся из `--tg-theme-*`: тема Telegram задаётся клиентом и может быть какой угодно, поэтому ей отдан только фон страницы.

Фирменная глина `#D97757` даёт на креме всего 3.0:1 — для текста мало. Поэтому коты рисуются чистой глиной, а текст и полосы берут затемнённый вариант того же тона.

## Деплой

Бот работает на long polling — белый IP и вебхук не нужны. Для Mini App
понадобится HTTPS-адрес: наружу его отдаёт обратный прокси, сам мини-апп
слушает только петлю.

```bash
docker compose up -d --build
```

Через тома переживают пересборку: база (`./data`), рабочие папки проектов
(`./workspaces`) и весь домашний каталог агента (`./claude-home`). Последний —
целиком, а не одна лишь `.claude`: настройки Claude Code лежат в `.claude.json`
рядом с папкой, и при монтировании только папки файл терялся на каждой сборке.

Контейнер бота отвечает на `/healthz`; docker опрашивает эту точку и помечает
зависший контейнер нездоровым. У прокси healthcheck не задан — в образе xray
нет ни шелла, ни утилит; вместо этого живость канала раз в десять минут
проверяет сам бот и переключается на запасной, а владельцу пишет в чат.

Копия базы снимается раз в сутки в `data/backups` через `VACUUM INTO` и хранится
неделю. Делает это сам процесс бота, поэтому на хосте ничего заводить не нужно.

Свой вывод бот пишет в `data/bot.log` и отдаёт хвост по `/logs` — изнутри
контейнера `docker logs` не прочитать, а пробрасывать туда docker-сокет значило
бы отдать агенту root на хосте.

### Сторож

Healthcheck помечает зависший контейнер нездоровым, но сам не перезапускает.
Этим занимается `scripts/watchdog.sh` — он живёт на хосте, потому что упавший
контейнер о себе сообщить не может. Три проваленные проверки подряд — и сторож
пишет владельцу в Telegram напрямую через Bot API, мимо самого бота, а потом
перезапускает контейнер. Когда бот вернётся, приходит ещё одна строка.

```bash
cp scripts/systemd/claude-telegram-watchdog.* /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now claude-telegram-watchdog.timer
```

### Кто может выкатываться

Автовыкатка запускает на сервере всё, что попало в `main`, — это цепочка
поставки, и она защищена списком авторов вне репозитория:

```bash
mkdir -p /etc/claude-telegram
printf '%s\n' 'твоя-почта@example.com' > /etc/claude-telegram/deploy-authors
chmod 600 /etc/claude-telegram/deploy-authors
```

Проверяется автор каждого коммита от текущего HEAD до цели, а не только
верхнего: иначе чужое пряталось бы под своим последним коммитом. Незнакомый
автор — выкатка останавливается и владельцу приходит сообщение с почтой.

### Автовыкатка

`.github/ci.yml` описывает те же проверки для GitHub Actions, но лежит не в
`.github/workflows/`: положить его туда может только токен с правом `workflow`.
GitHub отклоняет такой путь для OAuth-приложений, и ssh-ключ развёртывания не
помогает — он наследует ограничение приложения, которым создан. Включается
одной командой с машины владельца:

```bash
git mv .github/ci.yml .github/workflows/ci.yml && git commit -m "Включить CI" && git push
```

Пока этого не сделано, ту же работу делает сервер. `scripts/autodeploy.sh` раз
в три минуты смотрит, не появился ли в `main` новый коммит; если появился —
прогоняет формат, линтер, типы и тесты в одноразовом контейнере `node:24-slim`
и выкатывает только зелёное. Результат приходит владельцу в Telegram. Упавший
коммит не проверяется повторно: пока не запушат следующий, таймер молчит.

```bash
cp scripts/systemd/claude-telegram-autodeploy.* /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now claude-telegram-autodeploy.timer
```

Когда CI заработает в GitHub Actions, этот таймер надо выключить, иначе выкатка
пойдёт дважды:

```bash
systemctl disable --now claude-telegram-autodeploy.timer
```
