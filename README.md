# GPT Telegram

Telegram-бот с Codex CLI и входом через ChatGPT. Модели: GPT-6 Sol, GPT-6 Luna и GPT-6 Astra. У каждого пользователя отдельный Docker-контейнер, рабочие файлы, авторизация и история Codex.

Работающий бот: https://t.me/ChatGPT_ww_bot. Мини-апп открывается кнопкой «Мини-апп» в Telegram: список диалогов, поиск, суммаризации, выбор модели, режим разрешений, GPT-коты, мир и статистика. Вкладка «Проекты» группирует диалоги; каждый диалог имеет отдельные рабочие файлы.

Публичный адрес: https://gpt.103.88.241.202.sslip.io/chats.html. Авторизация — только через кнопку бота в Telegram.

## Запуск и обслуживание

На сервере установлены Node.js, Docker и Caddy. Управляющий процесс запускает systemd, пользовательские агенты — Docker. Точка входа: `gpt/main.mjs`.

```sh
cd /opt/ai-bot/app
systemctl status ai-bot
journalctl -u ai-bot -n 100 --no-pager
curl -fsS http://127.0.0.1:8788/healthz
```

Для сборки и проверки исходников:

```sh
npm ci --ignore-scripts
npm run build
npm test
npm run typecheck
```

`tsc` не копирует статические ресурсы. При обновлении мини-аппа скопируйте `src/miniapp/public/` в `dist/miniapp/public/`.

Образ пользовательского контейнера:

```sh
docker build -f gpt/Dockerfile.worker -t ai-worker:0.159.3 gpt
```

Альтернатива: `docker compose --profile build build worker-image`. Compose здесь собирает образ; работающий бот управляется `ai-bot.service`.

Для обновления управляющего процесса после выкладки собранных файлов:

```sh
systemctl restart ai-bot
```

Перезапуск останавливает выполняемые задачи. Перед обновлением проверьте активные задачи; сохранённые диалоги и файлы остаются на диске.

## Использование

- `/start` — меню; `/model` — выбор модели.
- `/chats` — все личные диалоги с постраничным просмотром; `/new` — новый диалог.
- `/delete` — отметить несколько диалогов на любых страницах, затем подтвердить полное удаление.
- `/project имя`, `/projects` — рабочие проекты.
- `/files`, `/file путь` — просмотр и скачивание файлов.
- `/permissions auto` — выполнение без запросов разрешений внутри контейнера; `/permissions read` — режим только чтения.
- `/stop` — остановка процессов задачи и очистка своей очереди.
- `/status`, `/tasks` — состояние; `/summary`, `/export` — контекст и переписка.
- `/rename название` — переименование диалога.
- `/git`, `/diff`, `/commit`, `/push`, `/clone URL` — поручения GPT для работы с Git внутри контейнера.
- `/app` — кот и мир. Кнопка меню открывает диалоги мини-аппа.
- Владелец: `/admin list`, `/admin add ID`, `/admin remove ID`.

Вход в ChatGPT предлагается кнопкой «Подключить ChatGPT». Команда входа не публикуется в подсказках. В текущей конфигурации у каждого пользователя собственный вход; токен владельца не копируется другим пользователям.

Документы и фото сохраняются в `.uploads/` текущего диалога. Используется облачный Telegram Bot API: скачивание вложений до 20 МБ, отправка файлов до 49 МиБ. Голосовые используют настроенный сервис расшифровки; подписка ChatGPT сама по себе не является ключом Audio API.

## Изоляция

Управляющий сервис хранит Telegram-токен и общую SQLite-базу. Агенты не получают к ним доступ. Контейнер `ai-user-ID` видит только два своих тома: домашнюю папку и рабочие проекты. В режиме чтения создаётся временный `ai-read-ID`: домашняя папка и проекты подключены read-only, запись доступна только в служебный `.codex` и временную папку. После задачи контейнер удаляется. Ограничения записи применяет Docker; дополнительные привилегии Linux не выдаются.

Контейнеры работают от UID 1000, с read-only корневой файловой системой, без Linux capabilities и повышения привилегий, без Docker-сокета и публикации портов. Ограничены память, CPU, число процессов и временная папка. Отдельная Docker-сеть запрещает соединения между пользователями, с хостом и приватными/служебными адресами. Внешние запросы идут напрямую, без пула прокси из старого проекта.

Модель не исполняет команды на хосте. Даже чтение/запись вложений выполняется через `docker exec`; пользовательские симлинки не разрешаются файловыми API управляющего процесса. Выбор диалога, экспорт и API мини-аппа проверяют владельца на стороне сервера. Mini App проверяет подпись и срок Telegram initData.

Проверки на сервере:

```sh
cd /opt/ai-bot/app
node gpt/verify-isolation.mjs
node gpt/smoke-codex.mjs
```

Вторая проверка вызывает модели и расходует лимиты ChatGPT: проверяет создание файла, команду, продолжение сессии и доступность всех трёх моделей. На сервере с 2 ГБ RAM задачи Telegram выполняются последовательно, чтобы не исчерпывать память. Контейнерная изоляция использует общий Linux kernel; отдельной VM для каждого пользователя нет.

## Данные и миграция

| Путь на сервере | Содержимое |
| --- | --- |
| `/opt/ai-bot/app/.env` | Закрытый конфиг управляющего сервиса |
| `/opt/ai-bot/data/bot.db` | Пользователи, доступы, статистика, новые диалоги и сообщения |
| `/opt/ai-bot/data/backups/` | Ежедневные копии базы; это не резервные копии всех рабочих файлов |
| `/opt/ai-bot/tenants/ID/workspace/` | Рабочие файлы конкретного пользователя |
| `/opt/ai-bot/tenants/ID/home/.codex/` | Авторизация аккаунта пользователя |
| `/opt/ai-bot/tenants/ID/workspace/.dialogs/UUID/` | Отдельные рабочие файлы диалога |
| `/opt/ai-bot/tenants/ID/home/dialogs/UUID/` | HOME, сессии Codex, кеши и исходная история только этого диалога |
| `/opt/ai-bot/tenants.btrfs` | Разреженный образ Btrfs, смонтированный в tenants |
| `/opt/gpt-migration/` | Отчёты; дубликаты исходного архива и восстановленных данных удалены после проверки |

Источник — архив от 1 октября 2026. Скрипты миграции не меняют исходный архив и чаты Claude. На старом сервере добавлен только вход мини-аппа через существующий домен; прочие приложения сохранены. Сохранены рабочие файлы, учётные записи и статистика. Старые ключи Claude удалены только из новой рабочей базы; они остаются в исходном архиве на Mac.

`prepare-migration.py` сопоставляет транскрипты с пользователями и изолирует рабочие папки. `summarize-history.py` обрабатывает все текстовые сообщения и сведения о действиях, сохраняет промежуточные результаты и отчёт покрытия. Успешные tool outputs и полные объёмные inputs остаются в исходных JSONL; в суммаризацию передаются текст переписки, действия и ошибки. `import-history.py` сохраняет исходные пользовательские названия, создаёт личные диалоги и публикует готовый контекст. При первом продолжении GPT получает суммаризацию и пути к полным исходникам; старый ID Claude не используется как ID Codex.

В источнике 106 файлов истории: 69 пользовательских диалогов с дочерними сессиями и 4 служебных диалога без надёжного владельца. Последние остаются в исходном архиве на Mac и не выданы случайному пользователю. Ещё одна запись чата имеет отсутствовавший уже в архиве транскрипт; другая не имела сессии. В интерфейс перенесена 71 запись с обозначением недостающих данных.

Перенос завершён: 73 группы обработаны без ошибок, покрыты все 106 исходных файлов; опубликовано 69 суммаризаций и 2 записи о недостающей истории. Временный суммаризатор и таймер импорта остановлены, временные копии ChatGPT-авторизации удалены.

Отчёт переноса:

```sh
systemctl status gpt-history-summarize-v2
journalctl -u gpt-history-import -n 10 --no-pager
tail -n 10 /opt/gpt-migration/summarize.log
```

## Настройки

Обязательные переменные: `BOT_TOKEN`, `ENCRYPTION_KEY`, `ALLOWED_USER_IDS` (начальный список доступа; владелец админки — `1057399602`). `DATA_DIR` задаёт каталог базы, `TENANT_ROOT` — каталог личных контейнерных томов. `MINIAPP_URL` — HTTPS-адрес, `MINIAPP_PORT` — локальный порт HTTP-сервера. Голосовые: `WHISPER_URL`, `WHISPER_MODEL`, `WHISPER_TOKEN`.

Активный код бота находится в `gpt/`; переиспользуемые модули базы, статистики и мини-аппа — в `src/`. Старые Claude-обработчики сохранены для сравнения и не используются новой точкой входа. Claude SDK оставлен только в devDependencies для типов этих модулей. Старые инструкции и конфиги помещены в `docs/legacy-*`; прежние скрипты авторазвёртывания и прокси на новом сервере не включены.


## Админка

Владелец `1057399602` видит вкладку «Админка»: добавить пользователя по Telegram ID, изменить заметку, дневной бюджет токенов и максимум диалогов, удалить или вернуть доступ. Решения администратора перекрывают `ALLOWED_USER_IDS`. При удалении доступа текущая задача/вход останавливается, очередь очищается; файлы и диалоги сохраняются.

Для диалогов по умолчанию и максимум — 5 у каждого пользователя; только владелец имеет неограниченное число. Администратор может снизить лимит до 0–5. При превышении уже существующим числом нужно сначала удалить лишние через `/delete`; автоматически чаты не удаляются. Пустой лимит токенов означает отсутствие ограничения; ноль запрещает новые задачи. Диалоги, перенесённые из Claude, входят в число существующих. Бюджет токенов учитывает вход и выход, включая кеш, по событиям Codex в `gpt_token_daily`; сброс — 00:00 UTC. Проверка выполняется при постановке в очередь и перед стартом. Завершающаяся задача может превысить остаток, поскольку CLI сообщает окончательный расход после выполнения. Этот бюджет бота не отражает ограничения подписки ChatGPT.

Админ API проверяет фиксированный ID после проверки Telegram-подписи. Скрытая вкладка не является механизмом защиты: GET и POST от другого разрешённого пользователя возвращают 403. Отключённому пользователю закрыты и старые API профиля/мира.

## Доступность мини-аппа

Публичный вход: `gpt.103.88.241.202.sslip.io`, HTTPS и HTTP/2 с `Alt-Svc: clear`. В логах Telegram WebKit обнаружены зависшие QUIC/HTTP3-соединения к прежнему адресу; сама зона `.ru` не доказана как причина. Новый адрес проверен WebKit с настоящим Telegram SDK и внешним узлом в Украине.

Веб-вход находится на старом сервере `103.88.241.202` в Москве, бот и данные — в Нидерландах. Caddy передаёт запросы через закрытый локальный порт 18788. Защищённое соединение Chisel 1.10.1 инициируется из Нидерландов через `wss://daktntgos.ru/gpt-connect`; браузер использует sslip.io. Мост применяет отдельные credentials и проверку SSH fingerprint; разрешён только обратный адрес `127.0.0.1:18788`. GPT/OpenAI и Telegram доступны из нового сервера напрямую, без старых исходящих прокси. Доступность из всех сетей страны не гарантируется одной внешней проверкой.

- Новый сервер: `gpt-web-ingress.service`, `/opt/ai-ingress/client.env` (0600).
- Старый сервер: `gpt-ingress-server.service`, `/opt/ai-ingress/auth.json` и `server.pem` (0600, пользователь `gpt-ingress`).
- Конфигурации systemd сохранены в `gpt/ingress-*.service`; секреты в исходники не включены.
- При недоступности сети интерфейс завершает ожидание API через 12 секунд и предлагает повторить запрос.
- Старые сообщения с прямой ссылкой могут содержать прежний адрес: откройте новое меню через `/start`.

Проверка с внешней сети: `curl -fsS https://gpt.103.88.241.202.sslip.io/chats.html`. Проверка локального приложения: `curl -fsS http://127.0.0.1:8788/healthz`. При остановке любого из двух серверов мини-апп недоступен; Telegram-бот и контейнеры работают на новом сервере независимо от веб-входа.

## Удаление и отдельные папки диалогов

`/delete` использует выбор с пагинацией и одно подтверждение выбранного набора. Проверяется владелец каждого ID. Работа в выбранном диалоге останавливается; если выполняется другой диалог, удаление просит сначала завершить его. Удаляются папки работы и HOME, сообщения, summary, задания и привязки, затем записи из ежедневных серверных копий SQLite. При сбое очистка остаётся незавершённой и повторяется через `/delete` или при перезапуске. Tombstone хранит только идентификаторы и статус; повторный импорт закрыт маркером `data/dialog-layout-v2.json`.

Старые общие проекты перенесены независимыми reflink-копиями Btrfs: файлы имеют разные inode, изменения и удаление одного диалога не затрагивают другой. На старте такие копии разделяют только физические блоки диска; блок освобождается, когда на него больше не ссылается ни одна копия. Старый проект мог обслуживать несколько диалогов, поэтому каждый из них получает его исходное состояние. Новые диалоги начинаются с пустой папки. Разные диалоги одного пользователя находятся внутри одного пользовательского контейнера; граница безопасности проходит между пользователями.

Образ монтируется через `/etc/fstab`; Docker и бот имеют `RequiresMountsFor=/opt/ai-bot/tenants`, чтобы не запуститься на пустой папке при проблеме монтирования. При восстановлении нужны и образ, и актуальная база. Исходный ZIP на Mac сохранён; очистка из бота не изменяет этот архив и оригинальные чаты Claude.
