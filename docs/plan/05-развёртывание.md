# Развёртывание на новый сервер

## Что нужно от сервера

- Docker и Docker Compose
- 2 ГБ свободного места под образ (сам образ ~1.2 ГБ)
- Любой обратный прокси с TLS для мини-аппа: Caddy, nginx, Traefik
- Выход в интернет; до `api.anthropic.com` — напрямую или через прокси

## Порядок

1. **Скопировать код** и создать `.env` из `.env.example`.
2. **Заполнить обязательное**: `BOT_TOKEN`, `ALLOWED_USER_IDS`, `ENCRYPTION_KEY`
   (генерится `npm run keygen`).
3. **Проверить выход**: сервис на старте сам определит, нужен ли прокси, и
   напишет вывод в лог. Если нужен — заполнить `PROXY_POOL`.
4. **Поднять**: `docker compose up -d --build`.
5. **Прописать домен** в обратном прокси на `127.0.0.1:8788` и вписать
   получившийся HTTPS-адрес в `MINIAPP_URL`, затем перезапустить контейнер.
6. **Войти в боте**: `/start` → способ входа → токен.

## Грабли, на которые уже наступили

**Место на диске.** На общем сервере было занято 98%. Спасает
`docker builder prune -af` — вернуло 16 ГБ. Проверять до сборки, а не после.

**Caddy с `admin off`.** `systemctl reload caddy` ходит в админ-API на порту
2019; при `admin off` он не слушает, и reload падает. Единственный способ
применить конфиг — `systemctl restart caddy`, а это кратковременно роняет все
сайты на этом сервере. Порядок: бэкап конфига → `caddy validate` → рестарт →
сразу проверить соседей → при провале откатить.

**Обрыв SSH на длинной сборке.** На сервере с троттлингом SSH сборка обрывается
вместе с сессией и продолжает идти в фоне. Вторая попытка налетает на тот же тег
и падает с `image already exists`. Запускать сборку через `nohup`, а прогресс
смотреть отдельным заходом.

**Секреты в образе.** `.env` в `.dockerignore`, а в контейнер попадает через
`env_file` в compose. Значит токены не запекаются в слои и не уедут вместе с
образом.

**Один токен — один поллер.** Два процесса с одним `BOT_TOKEN` конфликтуют на
long polling. Перед запуском на сервере погасить локальный.

**Нативный бинарь.** `npm ci --include=optional` обязателен: исполняемый файл
Claude Code приезжает опциональной зависимостью под платформу. Без него SDK не
найдёт, что запускать. Проверка:
`ls node_modules/@anthropic-ai/claude-agent-sdk-linux-x64/claude`.

## Текущая установка

| | |
|---|---|
| Сервер | 203.0.113.10, Ubuntu 24.04 |
| Контейнер | `claude-telegram`, образ 1.23 ГБ |
| Каталог | `/opt/claude-telegram` |
| Мини-апп | `https://claudebot.203.0.113.10.sslip.io` |
| Прокси | `http://egress-proxy:1080`, сеть `telegram-archive_egress` |
| Домены | через sslip.io, TLS выдаёт Caddy автоматически |

Сервер общий, на нём около 40 контейнеров и 24 сайта. Всё, что трогает Caddy или
диск, задевает соседей — отсюда бэкапы и проверки выше.

## Открытые вопросы

- Нужен ли скрипт установки одной командой, или compose достаточно? Пока шагов
  немного, но шаг с обратным прокси руками — самый неудобный.
- Как обновлять: пересборка образа или `git pull` внутрь контейнера? Пересборка
  честнее, но на слабом сервере долгая.
