# План: Claude Code как сервис в Telegram

Рабочие документы, чтобы не держать замысел в голове. Пишутся до кода и правятся
по мере того, как гипотезы проверяются на практике.

## Что строим

Сервис, который разворачивается на любом сервере одной командой и даёт полный
Claude Code внутри Telegram: чат с агентом, разрешения кнопками, голосовые,
пересланные сообщения и мини-апп со статистикой подписки.

## Три решения, на которых всё держится

**Вход по подписке, а не по API.** `claude setup-token` выдаёт долгоживущий
токен, тот уходит агенту как `CLAUDE_CODE_OAUTH_TOKEN`. Работа идёт по лимитам
подписки. Подробности и почему это не нарушает правила SDK — в
[01-архитектура.md](01-архитектура.md).

**Лимиты приходят событием, а не запросом.** У SDK нет метода «покажи остаток».
Есть событие `rate_limit_event` в потоке сообщений сессии. Значит статистика
обновляется по ходу работы и мини-апп показывает последнее известное значение —
это ограничение, а не недоделка. См. [03-лимиты-и-миниапп.md](03-лимиты-и-миниапп.md).

**Прокси нужен не всегда.** Он включается, только если сервер в стране, откуда
Anthropic отвечает отказом. Проверка делается на старте, а не задаётся руками.
См. [02-сеть-и-прокси.md](02-сеть-и-прокси.md).

## Как пользоваться этими документами

Каждый документ отвечает на один вопрос и заканчивается разделом «Открытые
вопросы» — туда попадает то, что ещё не проверено на практике. Когда вопрос
закрывается, он переезжает в текст с пометкой, чем именно подтверждён.

Не переписывай документ, если гипотеза не подтвердилась: допиши, что проверили
и что получилось. Иначе через месяц будет непонятно, почему сделано именно так.
